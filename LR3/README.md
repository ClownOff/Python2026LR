# Домашняя работа №4. HelpDesk

## Что нужно разработать

Создайте консольную программу для небольшой службы поддержки. Оператор добавляет заявки, переводит их в работу, закрывает, просматривает результаты поиска и журнал действий.

Это одно приложение: классы хранят состояние, генераторы выдают результаты по запросу, декоратор записывает действия. На работу отводится **две недели**. Ориентировочная нагрузка — **6–10 часов**; удобнее выполнять её несколькими подходами.

Все данные находятся в памяти и исчезают после завершения программы. Сеть, файлы и база данных не нужны.

Не нужны `itertools`, рекурсия, `send`, контекстные менеджеры и сторонние библиотеки. Новых обязательных тем для самостоятельного изучения нет.

## 1. Заявка — класс Ticket

```python
class Ticket:
    def __init__(self, ticket_id, title, *, category, priority=1):
        ...
```

Каждая заявка хранит собственные атрибуты:

| Атрибут | Значение |
|---|---|
| `ticket_id` | Положительный целый идентификатор |
| `title` | Непустое название без лишних пробелов |
| `category` | Непустая категория в нижнем регистре |
| `priority` | Целое число от 1 до 3: 3 — самый высокий приоритет |
| `status` | При создании всегда `"new"` |

Типы аргументов считаются правильными. Проверять нужно значения: положительный ID, непустые название и категорию, диапазон приоритета. При нарушении правила возбуждайте `ValueError` с понятным сообщением.

У названия удалите пробелы по краям и замените последовательности пробельных символов одним пробелом. У категории удалите пробелы по краям и вызовите `lower()`.

### Методы заявки

| Метод | Поведение и результат |
|---|---|
| `start()` | Переводит `new` в `in_progress`; возвращает `None` |
| `close()` | Переводит `in_progress` в `closed`; возвращает `None` |
| `to_dict()` | Возвращает новый словарь с данными заявки |

Любой другой переход через `start` или `close` вызывает `ValueError`. Состояние при ошибке остаётся прежним. Например, нельзя закрыть новую заявку, повторно начать уже начатую или повторно закрыть закрытую.

```python
ticket = Ticket(1, "  Не   работает Wi-Fi  ", category=" Network ", priority=3)
print(ticket.to_dict())
# {
#     "id": 1,
#     "title": "Не работает Wi-Fi",
#     "category": "network",
#     "priority": 3,
#     "status": "new",
# }

ticket.start()
ticket.close()
print(ticket.status)  # closed
```

В словаре ключ называется `id`, а в объекте атрибут — `ticket_id`. Все значения словаря — строки и числа. Изменение словаря из `to_dict()` не должно менять объект.

Не требуется запрещать прямую запись атрибутов. По правилам приложения статусы меняются только через методы.

## 2. Служба поддержки — класс HelpDesk

```python
class HelpDesk:
    def __init__(self):
        ...
```

Каждый экземпляр содержит:

- `self._tickets` — словарь `id → объект Ticket`;
- `self._next_id` — следующий ID, первоначально 1;
- `self._history` — список записей журнала, первоначально пустой.

Это обычные атрибуты. Начальное подчёркивание — соглашение о внутреннем использовании, а не специальный механизм доступа. Глобальные словари заявок и журналов запрещены.

### Операции с заявками

| Метод | Действие | Возвращает |
|---|---|---|
| `add_ticket(title, *, category, priority=1)` | Создаёт и сохраняет `Ticket` со следующим ID | Словарь новой заявки |
| `get_ticket(ticket_id)` | Находит заявку | Новый словарь её данных |
| `start_ticket(ticket_id)` | Вызывает у заявки `start()` | Новый словарь после изменения |
| `close_ticket(ticket_id)` | Вызывает у заявки `close()` | Новый словарь после изменения |

Объект `Ticket` наружу через эти методы не возвращается. Используйте `to_dict()`.

Если ID не найден, `get_ticket`, `start_ticket` и `close_ticket` возбуждают `KeyError`. Некорректное создание или недопустимый переход состояния вызывает `ValueError`.

Неудачная операция не меняет заявки, следующий ID и журнал. Например, после неудачного создания первой заявки следующее успешное создание всё ещё получает ID 1.

Разные экземпляры `HelpDesk` независимы: каждый начинает нумерацию с единицы.

## 3. Генераторы просмотра

### Поиск заявок

```python
def iter_tickets(self, *, status=None, category=None, min_priority=1, query=""):
    ...
```

Метод `HelpDesk` выдаёт по одному **новому словарю** подходящих заявок в порядке создания.

- `status=None` — любой статус; иначе только указанный.
- `category=None` — любая категория; иначе очистите параметр и приведите к нижнему регистру.
- `min_priority` — минимальный разрешённый приоритет, включая границу.
- `query` — подстрока в названии без учёта регистра; пробелы по краям запроса удаляются. Пустой запрос не ограничивает поиск.
- Все фильтры действуют одновременно.

Для фильтров предполагаются правильные типы и допустимые значения. Отдельная валидация фильтров не требуется.

Метод должен использовать `yield`. Нельзя сначала собирать полный список найденных заявок. Копия данных конкретной заявки создаётся, когда генератор выдаёт эту заявку.

```python
for item in desk.iter_tickets(status="new", min_priority=2, query="почту"):
    print(item["title"])
```

### Просмотр журнала

`HelpDesk.iter_history()` выдаёт через `yield` новые копии записей журнала в порядке их добавления. Изменение выданного словаря не меняет сохранённую запись.

Во время одного обхода генератора заявки и журнал не изменяются. Для просмотра обновлённого состояния создайте новый генератор. Исчерпанный генератор не начинает обход заново.

## 4. Декоратор audit_action

```python
def audit_action(action):
    ...
```

Фабрика создаёт декоратор для методов `HelpDesk`, возвращающих словарь заявки. Примените его к трём методам:

```python
@audit_action("create")
def add_ticket(self, title, *, category, priority=1):
    ...

@audit_action("start")
def start_ticket(self, ticket_id):
    ...

@audit_action("close")
def close_ticket(self, ticket_id):
    ...
```

Обёртка принимает `self`, `*args`, `**kwargs` и выполняет шаги:

1. Вызывает исходный метод один раз.
2. После получения результата добавляет запись в `self._history`.
3. Возвращает исходный результат без изменения.

Формат записи:

```python
{
    "number": 1,        # номер записи в журнале этого HelpDesk, с единицы
    "action": "create",
    "ticket_id": 1,    # из result["id"]
    "status": "new",   # из result["status"] на момент действия
}
```

Создавайте отдельный словарь записи: не сохраняйте весь `result` как запись журнала. Номер удобно получить из текущей длины журнала. Для сохранения имени и документации метода используйте `wraps`.

При исключении исходного метода запись не добавляется; исключение должно уйти вызывающему коду. Отдельный `try/except` в декораторе для этого не нужен: до добавления записи выполнение просто не дойдёт.

Не добавляйте запись ещё раз внутри методов. Просмотр, поиск и статистика журнал не изменяют. Декоратор не применяется к генераторам.

## 5. Просмотр пакетами

```python
def iter_batches(iterable, size):
    ...
```

Это отдельная генераторная функция в `helpdesk.py`. Она объединяет элементы любого iterable в кортежи длины `size`. Последний неполный пакет сохраняется, пустой источник не создаёт пакетов. Предполагается положительный целый `size`.

```python
for batch in iter_batches(desk.iter_tickets(status="new"), 2):
    for item in batch:
        print(item["title"])
```

Не превращайте весь источник в список и не читайте элемент следующего пакета до выдачи текущего. 

Небольшие примеры результата:

```python
print(list(iter_batches([10, 20, 30, 40, 50], 2)))
# [(10, 20), (30, 40), (50,)]

print(list(iter_batches([], 2)))
# []
```

Здесь `list` используется только для показа результата. В меню перебирайте пакеты последовательно, без преобразования генератора в список.

## 6. Общая статистика

`HelpDesk.summary()` возвращает новый словарь:

```python
{
    "total": 3,
    "by_status": {"new": 2, "in_progress": 0, "closed": 1},
    "by_category": {"network": 1, "mail": 1, "accounts": 1},
}
```

Считайте все заявки, а не только последний результат поиска. Все три статуса присутствуют всегда, даже при нулевом количестве. Категории появляются в порядке первого появления среди заявок; для пустой службы `by_category` равен `{}`.

Все возвращённые словари должны быть независимы от внутреннего состояния. Вызов статистики не меняет журнал.

## 7. Консольная программа

В `main.py` создайте один `HelpDesk` и меню:


Для просмотра заявок достаточно запросить статус: пустой ввод означает все статусы. Остальные фильтры покажите в демонстрационном сценарии ниже. Выводите заявки через `iter_batches(..., 2)`; после пакета пользователь может продолжить просмотр или вернуться в меню.

Если результаты поиска или журнал пусты, сообщите об этом. В остальных случаях формат вывода свободный: например, одна строка на заявку с ID, названием, статусом, категорией и приоритетом.

Обработайте `ValueError` и `KeyError` на уровне меню: выведите понятное сообщение и продолжите работу. Не подавляйте любые ошибки через общий `except Exception`. Точное оформление меню и текста отчётов свободное.

## Сквозной сценарий для самопроверки

```python
desk = HelpDesk()
desk.add_ticket(" Не   работает Wi-Fi ", category=" Network ", priority=3)
desk.add_ticket("Настроить почту", category="Mail", priority=2)
desk.add_ticket("Открыть доступ", category="Accounts", priority=1)

desk.start_ticket(1)
desk.close_ticket(1)

print([item["id"] for item in desk.iter_tickets(status="new", min_priority=2)])
# [2]

print([item["id"] for item in desk.iter_tickets(query="ПОЧТУ")])
# [2]

print(desk.summary())
# {
#     "total": 3,
#     "by_status": {"new": 2, "in_progress": 0, "closed": 1},
#     "by_category": {"network": 1, "mail": 1, "accounts": 1},
# }
```

Журнал после этих действий:

```python
[
    {"number": 1, "action": "create", "ticket_id": 1, "status": "new"},
    {"number": 2, "action": "create", "ticket_id": 2, "status": "new"},
    {"number": 3, "action": "create", "ticket_id": 3, "status": "new"},
    {"number": 4, "action": "start", "ticket_id": 1, "status": "in_progress"},
    {"number": 5, "action": "close", "ticket_id": 1, "status": "closed"},
]
```

Затем вызовите `desk.close_ticket(2)`: это `ValueError`, потому что заявка ещё `new`. В журнале остаётся пять записей, статус заявки 2 не меняется.

Дополнительно проверьте независимость двух `HelpDesk`, отсутствие расхода ID при неудачном создании и сохранность данных после изменения словаря из `get_ticket`.

Демонстрацию можно разместить отдельной функцией в `main.py`. Писать собственный тестовый набор не требуется.
