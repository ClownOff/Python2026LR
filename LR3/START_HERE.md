# HelpDesk: пояснение задания

## Что это за программа

Представьте оператора поддержки. Он записывает проблему, начинает её решать и закрывает после выполнения. Программа сохраняет заявки и историю действий, помогает найти нужные и показать общую картину.

Например, «Не работает Wi-Fi» — заявка категории `network` с высоким приоритетом. Сначала она `new`, затем `in_progress`, затем `closed`.

## Зачем два класса

**Ticket** отвечает за одну заявку: её данные и допустимые переходы состояния.

**HelpDesk** отвечает за набор заявок: выдаёт ID, хранит объекты, находит их и предоставляет операции оператору. Внутри его словаря находятся именно объекты `Ticket`, а наружу он возвращает копии данных в словарях.

```text
HelpDesk
    _tickets
        1 → Ticket «Не работает Wi-Fi»
        2 → Ticket «Настроить почту»
    _next_id → 3
    _history → записи выполненных действий
```

Это композиция: служба содержит заявки. Наследование для такой связи не нужно.

## Как выполняется одна команда

При вызове `desk.start_ticket(1)`:

1. Обёртка декоратора получает `desk` как `self` и аргумент `1`.
2. Исходный метод находит объект заявки.
3. Вызывает его `start()`.
4. Получает словарь через `to_dict()` и возвращает его обёртке.
5. Обёртка записывает действие `start` и новый статус в журнал.
6. Вызывающий код получает тот же результат метода.

Если заявка не найдена или переход запрещён, возникает исключение. До записи журнала выполнение не доходит.

## Где нужны генераторы

```python
results = desk.iter_tickets(status="new")
```

На этой строке создаётся генератор. Он не должен строить список всех найденных заявок. При запросе элемента он ищет следующее совпадение и выдаёт новый словарь.

`iter_history` работает так же для журнала. `iter_batches` объединяет результаты поиска в небольшие группы для показа в меню.

Сами заявки уже хранятся в памяти. Генераторы здесь экономят дополнительные списки результатов и позволяют прекратить просмотр раньше; они не делают хранилище заявок безразмерным.

## Где нужен декоратор

Создание, начало работы и закрытие должны оставлять записи одного формата. Вместо повторения кода журналирования в трёх методах его выполняет одна фабрика `audit_action`.

Обёртка метода отличается от обёртки обычной функции только явным первым аргументом:

```python
def wrapper(self, *args, **kwargs):
    ...
```

`self` — тот экземпляр `HelpDesk`, на котором вызвали метод. К его журналу обращайтесь обычным `self._history`. Никакой динамический поиск атрибутов не требуется.

Фабрика запоминает название действия, декоратор — исходный метод, обёртка получает конкретный экземпляр и аргументы вызова. `wraps` сохраняет метаданные исходного метода.

## В каком порядке писать

**1. Одна заявка.** Реализуйте `Ticket`, его проверки, `start`, `close` и `to_dict`. Создайте объект вручную, проведите по трём состояниям, попробуйте запрещённый переход.

**2. Хранилище.** Реализуйте `HelpDesk`: создание заявок, поиск по ID, начало работы и закрытие. Сначала убедитесь, что меняется нужный объект. Журнал пока может оставаться пустым.

**3. Журнал.** Напишите декоратор и подключите к трём методам. Проверьте, что один успешный вызов создаёт одну запись, а неудачный — ни одной. Не дублируйте запись внутри методов.

**4. Просмотр.** Добавьте генераторы поиска и журнала, затем пакетирование. Помните про последний неполный пакет и одноразовость генератора.

**5. Программа.** Добавьте статистику, меню и обработку двух ожидаемых типов ошибок. Выполните сквозной сценарий из README.

Этот порядок позволяет закончить небольшой работающий фрагмент за один подход и продолжить позже.

## На что обратить внимание

- Словари и журнал создаются в `__init__` каждого `HelpDesk`, а не общими атрибутами класса.
- Метод `Ticket.start()` меняет объект, а метод `HelpDesk.start_ticket()` ещё находит его и возвращает копию данных.
- Сначала проверяйте допустимость действия, потом меняйте состояние. Не увеличивайте ID до успешного создания заявки.
- Генератор выдаёт словари, а не внутренние объекты `Ticket`.
- Для нового просмотра вызывайте метод генератора заново. Не изменяйте хранилище в ходе одного обхода.
- Журнал сохраняет статус на момент действия: запись о создании останется `new`, даже когда сама заявка уже закрыта.
- Возвращённые словари можно менять, не затрагивая службу. Для вложенных словарей статистики тоже нужны независимые данные.

Точные сигнатуры, форматы результатов и правила ошибок находятся в README. Дополнительные механизмы управления атрибутами для выполнения работы не нужны.
